## 🧠 [1~15] Java 핵심 문법 & 객체지향

1️⃣ **Q:** `==`과 `.equals()`의 차이는?  
**A:** `==`는 주소(참조)를 비교하고, `equals()`는 객체의 내용(값)을 비교한다.

2️⃣ **Q:** `String`이 불변(immutable) 객체인 이유는?  
**A:** 한 번 생성된 문자열은 변경되지 않도록 설계되어 메모리 안정성과 보안성 확보를 위해서다.

3️⃣ **Q:** `final`, `finally`, `finalize()`의 차이?  
**A:** `final`은 수정 불가, `finally`는 예외 처리 후 항상 실행, `finalize()`는 GC(가비지컬렉터) 호출 시 실행된다.

4️⃣ **Q:** `static` 키워드의 의미는?  
**A:** 클래스 레벨에서 공유되는 변수/메서드로, 인스턴스 없이 접근 가능하다.

5️⃣ **Q:** 오버로딩(Overloading)과 오버라이딩(Overriding)의 차이는?  
**A:** 오버로딩은 같은 이름 다른 매개변수, 오버라이딩은 상속받은 메서드 재정의.

6️⃣ **Q:** 인터페이스와 추상 클래스의 차이?  
**A:** 인터페이스는 구현 강제, 추상 클래스는 공통 로직 포함 가능.

7️⃣ **Q:** `this`와 `super`의 차이?  
**A:** `this`는 자기 자신, `super`는 부모 클래스 참조.

8️⃣ **Q:** 예외 처리 `try-catch-finally`의 역할?  
**A:** 예외를 잡고(`catch`), 발생 여부와 상관없이 정리작업(`finally`) 수행.

9️⃣ **Q:** `NullPointerException`이란?  
**A:** null 객체의 메서드나 변수에 접근할 때 발생하는 런타임 오류.

10️⃣ **Q:** `List`와 `Set`의 차이?  
**A:** List는 순서O, 중복O / Set은 순서X, 중복X.

11️⃣ **Q:** `HashMap`과 `TreeMap` 차이?  
**A:** HashMap은 순서보장X, TreeMap은 키 기준 정렬O.

12️⃣ **Q:** `ArrayList`와 `LinkedList` 차이?  
**A:** ArrayList는 랜덤 접근 빠름, LinkedList는 삽입/삭제 빠름.

13️⃣ **Q:** `synchronized`의 역할은?  
**A:** 멀티스레드 환경에서 동시 접근을 막아 데이터 무결성 유지.

14️⃣ **Q:** JVM, JRE, JDK의 차이?  
**A:** JVM은 실행환경, JRE는 라이브러리+JVM, JDK는 개발도구+JRE.

15️⃣ **Q:** 객체지향 4대 특성은?  
**A:** 캡슐화, 상속, 다형성, 추상화.

## 🧩 [16~30] Spring & Backend 개념

16️⃣ **Q:** 스프링 프레임워크의 핵심 개념은?  
**A:** IoC(제어의 역전)과 DI(의존성 주입).

17️⃣ **Q:** @Autowired는 무엇인가?  
**A:** 스프링이 자동으로 필요한 객체를 주입(Injection)하는 어노테이션.

18️⃣ **Q:** @Controller와 @RestController의 차이?  
**A:** Controller는 뷰 반환, RestController는 JSON 데이터 반환.

19️⃣ **Q:** @Service와 @Repository의 역할은?  
**A:** @Service는 비즈니스 로직, @Repository는 DB 액세스 전용 컴포넌트.

20️⃣ **Q:** Spring Boot의 장점은?  
**A:** 설정 자동화, 내장 서버, 빠른 배포와 테스트.

21️⃣ **Q:** DTO와 Entity의 차이는?  
**A:** Entity는 DB 테이블과 매핑, DTO는 데이터 전송용 객체.

22️⃣ **Q:** @Transactional의 의미는?  
**A:** 메서드 내의 DB 작업을 하나의 트랜잭션으로 묶음 (실패 시 전체 롤백).

23️⃣ **Q:** AOP란?  
**A:** 관점 지향 프로그래밍. 로깅, 보안, 트랜잭션처럼 공통 기능을 분리.

24️⃣ **Q:** REST API란?  
**A:** HTTP 규약을 따르는 자원 중심의 API 설계 방식.

25️⃣ **Q:** HTTP 상태코드 200, 400, 401, 404, 500 의미?  
**A:** 200 성공, 400 잘못된 요청, 401 인증 실패, 404 없음, 500 서버오류.

26️⃣ **Q:** GET과 POST의 차이?  
**A:** GET은 조회(데이터 노출됨), POST는 전송(본문에 숨김).

27️⃣ **Q:** PUT과 PATCH의 차이?  
**A:** PUT은 전체 수정, PATCH는 일부 수정.

28️⃣ **Q:** JWT란?  
**A:** JSON Web Token. 사용자 인증정보를 암호화한 토큰 방식.

29️⃣ **Q:** API 병목 해결 방법은?  
**A:** 캐싱, 비동기 처리, DB 인덱스 튜닝, 부하분산 등.

30️⃣ **Q:** CORS란?  
**A:** Cross-Origin Resource Sharing, 도메인 간 자원 요청 제어 정책.

## 🗃️ [31~45] 데이터베이스 (SQL / MySQL)

31️⃣ **Q:** RDBMS란?  
**A:** 관계형 데이터베이스. 테이블 간 관계(키)를 기반으로 데이터 관리.

32️⃣ **Q:** 기본키(Primary Key)란?  
**A:** 각 행을 고유하게 식별하는 키.

33️⃣ **Q:** 외래키(Foreign Key)란?  
**A:** 다른 테이블의 기본키를 참조하는 키.

34️⃣ **Q:** 인덱스란?  
**A:** 검색속도를 향상시키는 데이터 구조.

35️⃣ **Q:** 인덱스의 단점은?  
**A:** 쓰기(CUD) 속도 저하, 추가 저장공간 필요.

36️⃣ **Q:** JOIN의 종류는?  
**A:** INNER, LEFT, RIGHT, FULL OUTER JOIN.

37️⃣ **Q:** GROUP BY의 역할은?  
**A:** 데이터를 특정 컬럼 기준으로 묶어 집계함수 적용.

38️⃣ **Q:** HAVING과 WHERE의 차이?  
**A:** WHERE는 그룹화 전 필터, HAVING은 그룹화 후 필터.

39️⃣ **Q:** 트랜잭션(Transaction)이란?  
**A:** 여러 DB 작업을 하나로 묶은 단위 (원자성 보장).

40️⃣ **Q:** COMMIT과 ROLLBACK의 차이?  
**A:** COMMIT은 영구 저장, ROLLBACK은 이전 상태로 복구.

41️⃣ **Q:** SQL Injection이란?  
**A:** 악의적인 쿼리를 삽입해 DB 조작하는 공격.

42️⃣ **Q:** View와 Inline View의 차이?  
**A:** View는 저장된 가상 테이블, Inline View는 쿼리 내 임시 서브쿼리.

43️⃣ **Q:** WITH문(Common Table Expression)은?  
**A:** 쿼리 내에서 재사용 가능한 임시 결과집합 정의.

44️⃣ **Q:** LIMIT과 OFFSET은?  
**A:** 조회 데이터 개수 제한(LIMIT)과 시작 위치 지정(OFFSET).

45️⃣ **Q:** DB 정규화란?  
**A:** 중복을 줄이고 데이터 무결성을 높이기 위한 테이블 구조화 과정.

## 🌐 [46~60] 네트워크 & HTTP

46️⃣ **Q:** 클라이언트와 서버의 차이?  
**A:** 클라이언트는 요청, 서버는 응답을 처리.

47️⃣ **Q:** IP와 MAC의 차이?  
**A:** IP는 논리적 주소, MAC은 물리적 네트워크 카드 주소.

48️⃣ **Q:** DNS란?  
**A:** 도메인명을 IP주소로 변환하는 시스템.

49️⃣ **Q:** HTTP와 HTTPS 차이?  
**A:** HTTPS는 SSL/TLS 암호화를 적용한 안전한 통신.

50️⃣ **Q:** 쿠키(Cookie)와 세션(Session) 차이?  
**A:** 쿠키는 클라이언트 저장, 세션은 서버 저장.

51️⃣ **Q:** 프록시 서버란?  
**A:** 클라이언트와 서버 사이에서 요청을 중계하는 서버.

52️⃣ **Q:** 로드밸런서의 역할은?  
**A:** 여러 서버로 트래픽을 분산해 부하를 줄임.

53️⃣ **Q:** TCP와 UDP의 차이?  
**A:** TCP는 연결형(신뢰성O), UDP는 비연결형(속도O).

54️⃣ **Q:** 포트 번호의 역할은?  
**A:** 한 컴퓨터에서 여러 서비스 구분 (HTTP:80, HTTPS:443 등)

55️⃣ **Q:** API 호출 시 3-way handshake란?  
**A:** TCP 연결 시 SYN → SYN-ACK → ACK 순서로 연결 설정.

56️⃣ **Q:** RESTful의 조건은?  
**A:** 자원 중심 URI, 무상태성(Stateless), 일관된 응답 형식.

57️⃣ **Q:** WebSocket은?  
**A:** 실시간 양방향 통신 프로토콜.

58️⃣ **Q:** CDN이란?  
**A:** 전 세계에 분산된 서버로 콘텐츠를 빠르게 전송.

59️⃣ **Q:** HTTP 헤더란?  
**A:** 요청/응답의 부가정보를 담는 데이터.

60️⃣ **Q:** Keep-Alive 옵션은?  
**A:** TCP 연결을 유지해 다중 요청 시 성능 향상.

## ⚙️ [61~80] 배포 / DevOps / 협업

61️⃣ **Q:** CI/CD란?  
**A:** 지속적 통합(Continuous Integration), 지속적 배포(Continuous Deployment).

62️⃣ **Q:** Docker의 역할은?  
**A:** 애플리케이션을 컨테이너로 격리해 일관된 실행 환경 제공.

63️⃣ **Q:** Dockerfile은 무엇을 정의하나?  
**A:** 컨테이너 이미지 빌드에 필요한 설정.

64️⃣ **Q:** Jenkins의 역할은?  
**A:** 자동 빌드/테스트/배포 도구.

65️⃣ **Q:** staging 환경이란?  
**A:** 배포 전 테스트용 실환경과 유사한 환경.

66️⃣ **Q:** rollback이란?  
**A:** 배포 실패 시 이전 버전으로 복구.

67️⃣ **Q:** 로깅(logging)은 왜 필요한가?  
**A:** 장애 추적, 디버깅, 성능 모니터링을 위해.

68️⃣ **Q:** 테스트 종류에는?  
**A:** 단위(Unit), 통합(Integration), 시스템(System), 인수(Acceptance).

69️⃣ **Q:** Git과 GitHub 차이?  
**A:** Git은 버전관리 도구, GitHub는 원격 저장소 서비스.

70️⃣ **Q:** merge와 rebase 차이?  
**A:** merge는 병합 커밋 생성, rebase는 커밋 이력 재정렬.

71️⃣ **Q:** PR(Pull Request)이란?  
**A:** 협업 시 코드 변경을 팀에 제안하는 요청.

72️⃣ **Q:** branch의 목적은?  
**A:** 독립된 작업공간 확보로 충돌 방지.

73️⃣ **Q:** commit message는 어떻게 써야 하나?  
**A:** “무엇을, 왜 변경했는지”를 간결히 (예: `fix: 로그인 예외처리 수정`)

74️⃣ **Q:** 버전 태깅(tag) 목적은?  
**A:** 특정 시점(배포 등)을 명시적으로 표시.

75️⃣ **Q:** YAML이란?  
**A:** 설정파일 포맷 (주로 CI/CD, Docker, Spring 설정에 사용)

76️⃣ **Q:** 환경변수(.env)의 역할은?  
**A:** 민감정보(DB, API키 등) 외부로 분리 관리.

77️⃣ **Q:** 로그레벨 INFO, WARN, ERROR 차이?  
**A:** INFO: 일반정보 / WARN: 주의 / ERROR: 치명적 오류.

78️⃣ **Q:** API 테스트 도구는?  
**A:** Postman, Swagger, Insomnia 등.

79️⃣ **Q:** Swagger의 역할은?  
**A:** API 문서 자동 생성 및 테스트 인터페이스 제공.

80️⃣ **Q:** 배포 후 바로 해야 할 확인은?  
**A:** 로그 모니터링, 주요 API 정상 호출, DB 커넥션 확인.

## 🧰 [81~100] 소프트스킬 & 실무 감각

81️⃣ **Q:** 코드리뷰의 목적은?  
**A:** 품질 향상, 버그 예방, 코드 일관성 유지.

82️⃣ **Q:** 리팩토링이란?  
**A:** 기능 변경 없이 코드 구조를 개선하는 작업.

83️⃣ **Q:** Clean Code의 핵심 원칙은?  
**A:** 가독성, 중복제거, 명확한 네이밍.

84️⃣ **Q:** 설계에서 가장 중요한 원칙?  
**A:** 변경에 유연하고, 중복이 없는 구조(SOLID 원칙).

85️⃣ **Q:** 단일 책임 원칙(SRP)이란?  
**A:** 클래스는 하나의 책임만 가져야 한다.

86️⃣ **Q:** 의존성 주입(DI)의 장점은?  
**A:** 테스트 용이성, 결합도 감소.

87️⃣ **Q:** 로깅 시 개인정보는?  
**A:** 민감정보(주민번호, 비밀번호)는 절대 기록 금지.

88️⃣ **Q:** 협업 시 코드 충돌 나면?  
**A:** git pull 후 merge conflict 해결 → commit → push.

89️⃣ **Q:** 팀에서 커밋 규칙 정하는 이유?  
**A:** 이력 관리와 협업 표준화.

90️⃣ **Q:** 테스트 코드를 작성하는 이유?  
**A:** 수정 시 기존 기능이 깨지지 않도록 검증.

91️⃣ **Q:** 오픈소스 라이선스 종류?  
**A:** MIT, Apache2.0, GPL 등 (재배포 조건 다름).

92️⃣ **Q:** API 버전 관리 방법?  
**A:** `/api/v1/...` 식으로 버전 분리.

93️⃣ **Q:** 장애 발생 시 첫 조치?  
**A:** 로그 분석 → 원인 추적 → 서비스 영향 최소화.

94️⃣ **Q:** 장애 재발 방지 방법?  
**A:** RCA(근본원인분석) 문서화 및 재발방지 대책 수립.

95️⃣ **Q:** 모니터링 도구 예시?  
**A:** Prometheus, Grafana, ELK Stack 등.

96️⃣ **Q:** 배포 자동화 장점은?  
**A:** 휴먼에러 감소, 일관된 결과.

97️⃣ **Q:** 캐싱의 목적은?  
**A:** 자주 쓰는 데이터를 메모리에 저장해 응답속도 향상.

98️⃣ **Q:** 동기 vs 비동기의 차이?  
**A:** 동기는 순차실행, 비동기는 기다리지 않고 병렬처리.

99️⃣ **Q:** API 응답 시간 늦을 때 진단 순서?  
**A:** 네트워크 → DB 쿼리 → 서버 CPU → 코드 로직 순.

100️⃣ **Q:** “좋은 개발자”란?  
**A:** 코드를 잘 치는 사람보다, 문제를 명확히 정의하고 협업으로 해결할 수 있는 사람.
