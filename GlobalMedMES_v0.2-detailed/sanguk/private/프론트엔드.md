# 🎨 프론트엔드 & React 기본기 100문제

---

## 🧱 [1~15] HTML 기본기

1️⃣ **Q:** HTML이란?  
**A:** 웹페이지의 구조를 정의하는 마크업 언어 (HyperText Markup Language).

2️⃣ **Q:** HTML5의 주요 특징은?  
**A:** 시맨틱 태그 도입(`<header>`, `<article>`), 멀티미디어 지원(`<video>`, `<audio>`), 로컬 스토리지.

3️⃣ **Q:** 시맨틱 태그란?  
**A:** 의미를 가진 태그로, 구조적이고 접근성 높은 페이지를 구성 (`<header>`, `<main>`, `<footer>` 등).

4️⃣ **Q:** `<div>`와 `<span>` 차이?  
**A:** `<div>`는 블록 요소(줄 바꿈), `<span>`은 인라인 요소(같은 줄).

5️⃣ **Q:** `<meta>` 태그는 어떤 용도인가요?  
**A:** 문서 정보 정의 (charset, viewport, SEO용 description 등).

6️⃣ **Q:** `<form>` 태그의 역할은?  
**A:** 사용자 입력을 서버로 전송하는 폼 영역 정의.

7️⃣ **Q:** `<input>` 태그의 주요 type 속성은?  
**A:** text, password, email, number, file, checkbox, radio 등.

8️⃣ **Q:** `<label>`과 `<input>`을 연결하는 방법은?  
**A:** `<label for="id명">` 속성과 `<input id="id명">` 속성 연결.

9️⃣ **Q:** `<a>` 태그의 기본 기능은?  
**A:** 하이퍼링크 생성 (`href` 속성).

10️⃣ **Q:** `<iframe>`의 역할은?  
**A:** 다른 HTML 문서를 현재 페이지 안에 삽입.

11️⃣ **Q:** SEO(Search Engine Optimization)에 유리한 HTML 구조는?  
**A:** 시맨틱 태그, 제목 구조(`<h1>~<h6>`), meta description 설정.

12️⃣ **Q:** `<script>` 태그의 위치는 왜 보통 body 하단에 두는가?  
**A:** 페이지 렌더링을 막지 않고 JS 실행을 나중에 하려는 이유.

13️⃣ **Q:** HTML에서 주석은 어떻게 작성하나?  
**A:** `<!-- 주석내용 -->`

14️⃣ **Q:** `<img>`의 필수 속성은?  
**A:** `src` (경로), `alt` (대체텍스트).

15️⃣ **Q:** 웹 접근성(Web Accessibility)이란?  
**A:** 장애인·비장애인 모두가 접근 가능한 웹사이트 구현 원칙.

## 🎨 [16~30] CSS 기초 및 스타일링

16️⃣ **Q:** CSS란?  
**A:** HTML 요소의 디자인(색상, 배치, 글꼴 등)을 정의하는 언어.

17️⃣ **Q:** 인라인 / 내부 / 외부 CSS의 차이?  
**A:** inline: 요소에 직접 / internal: `<style>` 태그 / external: `.css` 파일 연결.

18️⃣ **Q:** 선택자(Selector)란?  
**A:** 특정 HTML 요소를 선택해 스타일을 적용하는 문법.

19️⃣ **Q:** `#id`와 `.class` 차이?  
**A:** `#id`는 유일 요소, `.class`는 다중 요소에 적용 가능.

20️⃣ **Q:** `position` 속성의 종류는?  
**A:** static, relative, absolute, fixed, sticky.

21️⃣ **Q:** `display` 속성의 주요 값은?  
**A:** block, inline, inline-block, flex, grid.

22️⃣ **Q:** Flexbox의 장점은?  
**A:** 요소 정렬과 공간 분배를 간단하게 구현할 수 있음.

23️⃣ **Q:** Grid 레이아웃의 특징은?  
**A:** 2차원 행/열 기반 레이아웃 제공.

24️⃣ **Q:** `z-index`란?  
**A:** 요소의 쌓임 순서를 결정 (값이 클수록 위로).

25️⃣ **Q:** 반응형 디자인(Responsive Design)이란?  
**A:** 화면 크기에 따라 자동으로 적응하는 웹 레이아웃.

26️⃣ **Q:** `@media`의 역할은?  
**A:** 반응형 레이아웃 구현 시 특정 해상도 조건별 스타일 정의.

27️⃣ **Q:** `hover` 선택자는 언제 사용되나?  
**A:** 마우스 오버 시 효과를 줄 때.

28️⃣ **Q:** `transition` 속성의 역할은?  
**A:** 상태 변화 시 애니메이션 효과 추가.

29️⃣ **Q:** TailwindCSS의 특징은?  
**A:** 유틸리티 클래스 기반의 빠른 스타일링.

30️⃣ **Q:** `rem`과 `em`의 차이?  
**A:** `rem`은 루트 기준, `em`은 부모 요소 기준 크기 단위.

## ⚙️ [31~45] JavaScript 기초

31️⃣ **Q:** JavaScript란?  
**A:** 웹페이지의 동작을 제어하는 프로그래밍 언어.

32️⃣ **Q:** `var`, `let`, `const` 차이?  
**A:** var는 함수 스코프, let/const는 블록 스코프, const는 재할당 불가.

33️⃣ **Q:** `==` vs `===` 차이?  
**A:** `==`은 타입 변환 후 비교, `===`은 타입까지 일치 비교.

34️⃣ **Q:** 함수 선언식 vs 화살표 함수 차이?  
**A:** 선언식은 `function`, 화살표는 `() =>` 형태로 this 바인딩 다름.

35️⃣ **Q:** 클로저(closure)란?  
**A:** 함수가 선언될 때의 스코프를 기억해 외부 변수에 접근 가능한 구조.

36️⃣ **Q:** 비동기 처리란?  
**A:** 작업이 완료될 때까지 기다리지 않고 다음 코드 실행.

37️⃣ **Q:** Promise란?  
**A:** 비동기 작업의 성공/실패 상태를 표현하는 객체.

38️⃣ **Q:** async/await의 역할은?  
**A:** 비동기 코드를 동기식처럼 작성할 수 있게 함.

39️⃣ **Q:** JSON이란?  
**A:** 데이터 교환 형식 (JavaScript Object Notation).

40️⃣ **Q:** DOM(Document Object Model)이란?  
**A:** HTML 요소를 객체 트리로 표현한 구조.

41️⃣ **Q:** 이벤트 버블링(Event Bubbling)이란?  
**A:** 하위 요소에서 상위 요소로 이벤트가 전파되는 현상.

42️⃣ **Q:** `addEventListener()`의 세 번째 인자(capture 옵션)는?  
**A:** true면 캡처링 단계에서 실행, false면 버블링 단계에서 실행.

43️⃣ **Q:** `localStorage`와 `sessionStorage` 차이?  
**A:** local은 영구 저장, session은 탭 종료 시 삭제.

44️⃣ **Q:** `fetch()` 함수의 역할은?  
**A:** API 호출 등 네트워크 요청을 보냄 (Promise 기반).

45️⃣ **Q:** JavaScript에서 `this`는?  
**A:** 실행 컨텍스트(호출한 객체)에 따라 가리키는 대상이 달라진다.

## ⚛️ [46~70] React 기본

46️⃣ **Q:** React란?  
**A:** UI를 효율적으로 렌더링하기 위한 JavaScript 라이브러리.

47️⃣ **Q:** SPA(Single Page Application)이란?  
**A:** 페이지 전체를 새로고침하지 않고 부분만 갱신하는 웹앱 구조.

48️⃣ **Q:** Virtual DOM이란?  
**A:** 실제 DOM을 복제한 가상 객체로, 변경된 부분만 효율적으로 갱신.

49️⃣ **Q:** JSX란?  
**A:** JavaScript 안에서 HTML 문법을 사용할 수 있게 하는 확장 문법.

50️⃣ **Q:** 컴포넌트(Component)란?  
**A:** 재사용 가능한 UI 단위 (함수형/클래스형 존재).

51️⃣ **Q:** props란?  
**A:** 부모 컴포넌트가 자식에게 전달하는 데이터.

52️⃣ **Q:** state란?  
**A:** 컴포넌트 내부에서 관리되는 동적인 데이터.

53️⃣ **Q:** useState 훅의 역할은?  
**A:** 컴포넌트의 상태(state)를 관리하기 위한 훅.

54️⃣ **Q:** useEffect 훅의 역할은?  
**A:** 컴포넌트가 렌더링될 때 부수효과(데이터 요청, 구독 등)를 처리.

55️⃣ **Q:** useEffect의 의존성 배열([]) 의미는?  
**A:** 배열 안 값이 변경될 때만 effect 실행. 비우면 마운트 시 1회만 실행.

56️⃣ **Q:** 컴포넌트 재렌더링이 일어나는 경우는?  
**A:** state나 props가 변경될 때.

57️⃣ **Q:** React의 key 속성은 왜 중요한가?  
**A:** 리스트 렌더링 시 요소 식별을 위해 사용 (변경 감지 효율 ↑).

58️⃣ **Q:** Controlled Component란?  
**A:** 입력값을 state로 완전히 제어하는 폼 요소.

59️⃣ **Q:** Context API란?  
**A:** 여러 컴포넌트 간 데이터 공유를 위한 전역 상태 관리 도구.

60️⃣ **Q:** React에서 비동기 데이터 가져올 때 흔히 사용하는 훅은?  
**A:** useEffect와 fetch/axios.

61️⃣ **Q:** React Router의 역할은?  
**A:** URL 경로에 따라 다른 컴포넌트를 렌더링.

62️⃣ **Q:** BrowserRouter와 HashRouter의 차이?  
**A:** BrowserRouter는 실제 경로 기반, HashRouter는 #기반 가상경로.

63️⃣ **Q:** Route와 Link의 역할은?  
**A:** Route는 컴포넌트 렌더링, Link는 경로 이동.

64️⃣ **Q:** React에서 key props는 어디에 써야 하나?  
**A:** map()으로 리스트 렌더링할 때 최상위 요소에 부여.

65️⃣ **Q:** 상태 끌어올리기(Lifting state up)이란?  
**A:** 공통 조상을 통해 여러 자식이 같은 상태를 공유하도록 함.

66️⃣ **Q:** React.Fragment(`<></>`)는 무엇인가?  
**A:** 불필요한 DOM 생성 없이 여러 요소를 그룹화.

67️⃣ **Q:** useRef의 역할은?  
**A:** DOM 접근 또는 렌더링 사이에서 값 유지.

68️⃣ **Q:** memo()의 역할은?  
**A:** props 변경 없을 때 재렌더링 방지.

69️⃣ **Q:** useMemo와 useCallback의 차이?  
**A:** useMemo는 값 캐싱, useCallback은 함수 캐싱.

70️⃣ **Q:** Error Boundary란?  
**A:** 렌더링 중 발생한 JS 오류를 감지하고 대체 UI를 보여주는 기능.

## 🧠 [71~85] 상태관리 / 고급 패턴

71️⃣ **Q:** 상태관리란?  
**A:** 여러 컴포넌트 간의 데이터 일관성을 유지하는 방법.

72️⃣ **Q:** Redux의 주요 개념 3가지?  
**A:** Store, Action, Reducer.

73️⃣ **Q:** Redux Toolkit의 장점은?  
**A:** 보일러플레이트 코드 감소, 직관적인 createSlice API.

74️⃣ **Q:** Zustand란?  
**A:** 경량 상태관리 라이브러리 (React hook 기반).

75️⃣ **Q:** Recoil의 특징은?  
**A:** React 전용 전역 상태관리 라이브러리 (atom 단위).

76️⃣ **Q:** React Query의 역할은?  
**A:** 서버 상태(fetching/caching/sync)를 자동 관리.

77️⃣ **Q:** 서버 상태(Server state)와 클라이언트 상태(Client state)의 차이?  
**A:** 서버 상태는 API 데이터, 클라이언트 상태는 UI 관련 상태.

78️⃣ **Q:** Suspense란?  
**A:** 비동기 로딩 상태를 깔끔하게 처리하는 React 기능.

79️⃣ **Q:** ErrorBoundary와 Suspense 차이?  
**A:** ErrorBoundary는 오류 처리, Suspense는 로딩 처리.

80️⃣ **Q:** React에서 성능 최적화 방법 3가지?  
**A:** memoization(useMemo/useCallback), Lazy Loading, Virtualization.

81️⃣ **Q:** Lazy Loading이란?  
**A:** 필요할 때만 컴포넌트를 불러오는 방식.

82️⃣ **Q:** Virtualization이란?  
**A:** 화면에 보이는 요소만 렌더링해 성능을 높이는 기술.

83️⃣ **Q:** Custom Hook이란?  
**A:** 반복되는 로직을 재사용하기 위해 만든 사용자 정의 훅.

84️⃣ **Q:** Prop Drilling이란?  
**A:** 여러 단계 컴포넌트를 거쳐 props 전달하는 현상.

85️⃣ **Q:** Prop Drilling의 해결 방법은?  
**A:** Context API, Zustand, Redux 사용.

## 🚀 [86~100] 빌드 / 배포 / 협업

86️⃣ **Q:** CRA(Create React App)이란?  
**A:** React 프로젝트 초기 세팅 자동화 도구.

87️⃣ **Q:** Vite의 장점은?  
**A:** 빠른 빌드 속도, 경량 개발 서버.

88️⃣ **Q:** Babel의 역할은?  
**A:** 최신 JS 문법을 구형 브라우저 호환 코드로 변환.

89️⃣ **Q:** Webpack의 역할은?  
**A:** 여러 자원을 하나의 번들로 묶는 모듈 번들러.

90️⃣ **Q:** ESLint란?  
**A:** 코드 스타일 및 문법 오류 자동 검사 도구.

91️⃣ **Q:** Prettier란?  
**A:** 코드 포맷터. 일관된 코드 스타일 유지.

92️⃣ **Q:** npm과 yarn의 차이?  
**A:** 둘 다 패키지 관리자, yarn이 병렬 설치로 더 빠름.

93️⃣ **Q:** `package.json`의 역할은?  
**A:** 프로젝트의 의존성, 스크립트, 메타정보 관리.

94️⃣ **Q:** `.env` 파일의 역할은?  
**A:** 환경변수(DB URL, API KEY 등)를 별도로 관리.

95️⃣ **Q:** 빌드와 배포의 차이?  
**A:** 빌드는 실행 가능한 코드로 변환, 배포는 서버에 올려 서비스.

96️⃣ **Q:** React 앱을 S3나 Netlify에 배포할 때 필요한 명령어는?  
**A:** `npm run build` 후 생성된 `/build` 폴더를 업로드.

97️⃣ **Q:** CSR(Client Side Rendering)과 SSR(Server Side Rendering)의 차이?  
**A:** CSR은 클라이언트 렌더링, SSR은 서버에서 HTML 생성 후 전달.

98️⃣ **Q:** Next.js의 특징은?  
**A:** SSR, 정적 생성(SSG), API 라우팅 등 React의 확장 프레임워크.

99️⃣ **Q:** Lighthouse는 어떤 도구인가?  
**A:** 구글 제공 웹 성능·접근성 분석 도구.

100️⃣ **Q:** 프론트엔드 협업에서 중요한 역량은?  
**A:** 명확한 커뮤니케이션, 컴포넌트 분리 설계, 코드 일관성.
