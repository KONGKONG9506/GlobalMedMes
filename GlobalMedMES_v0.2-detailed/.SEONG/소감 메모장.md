KPI 
-KPI는 두개의 종류가 있음
-새로운 실적이 생길 때 마다 해당 작업지시의 실적들을 바탕으로 새로 생기는 실시간 KPI
-실시간 KPI는 작업지시마다 1개만 존재함

-서버가 동작하고 있을때 매일 일정시간에 이전날의 실적을 종합하여 만드는 일일 KPI
-일일 KPI는 설비 + 공정마다 1개만 존재함

인원배치
-인원을 배치할때 한 설비에 여러 인원을 함께 배치 가능
-인원을 배치할때 해당 설비에 자격증이 필요한 경우 자격증이 없는 인원은 배치 할 수 없음
-여러 인원을 배치했을 경우 직급이 높거나 장기 근속자 "이름 외 n명" 식으로 보여짐
(선임, 인턴 or 여럿이 필요한 공정)

작업지시
-작업지시의 상태를 R로 변화 시킬때 만약 교대 관리에서 직원을 배치하지 않았을 경우 직원이 배치되지 않았다는 에러가 남
-직원을 배치 하였어도 해당 작업지시의 공정에 필요한 자격증을 배치된 직원이 가지고 있지 않으면 설비를 가동 할 수 없음
단 배치된 직원 중 한명이라도 해당 공정의 자격증을 가지고 있다면 설비를 가동 할 수 있음

느낀점
-테이블의 개수가 생각보다 많이 나왔다.
지금껏 해본 원데이 프로젝트나 작년에 했던 파이널 프로젝트에선 테이블을 8개에서 10개 정도로 사용해서 했었는데
이번 프로젝트에선 초기 계획에서만 30개가 넘는 테이블을 쓴다해서 놀랐었다.
이후 목적을 설정하면서 몇개 줄이긴 했지만 프로젝트를 하다보니 다시 테이블을 늘려서 42개의 테이블을 사용했다.

-로직이 짜기가 힘들었다.
그냥 원하는 기능을 넣는건 오래해봤자 2~3일 이면 얼추 넣었었는데 이번에 KPI를 하면서 많이 힘들었다.
KPI를 그냥 하드코딩으로 하는게 아니라 데이터베이스에 계산식을 넣고 이를 통해서 수율, 생산량 등을 계산하려고 하니까
에러가 나와서 당황했었다. 원래는 데이터베이스에는 그냥 수식만 넣으려 했었는데 이게 잘안되서 SpEL 수식으로 데이터베이스에 저장했었다.
그렇게 했는데 OEE를 계산하려고 하니까 신경 써야 할게 많고 다른 기능의 구현도 필요해서 다른 계산식을 구현하고 OEE를 구현할 준비만 해도 1주일 가량 걸렸던 것 같다.
특히 비가동 시간이 오래 걸렸는데
처음엔 비가동 시간을 하나의 상태로만 하려 했다가 잘 안돼서 비가동(시작), 비가동(종료) 두개로 바꿔야했고
비가동 시간도 계획된 비가동시간(쉬는시간)과 계획되지 않은 비가동시간(고장)이 있어서 이걸 구하려면 또 계획된 비가동 시간을 정해야해서 관련된 테이블과 코드를 짜는등 해야할게 매우 많아서 힘들었다.
그리고 이를 통해서 비가동 시간도 구했는데 막상 시험해보니 OEE가 부정확하게 나와서 다시 수정하고 다시 시험하니 아예 반영이 안되고 그러다가 로그를 통해 하나하나 읽으면서 고쳐나가니까 마지막엔 OEE가 제대로 나와서 KPI를 완성할 수 있었다.
근데 또 KPI를 해당 작업지시 단위로 하기위해 여러가지를 수정한다던가 같은 테이블에서 실시간 KPI와 일일 KPI를 함꼐 하려고 하니까 중복에러가 일어난다던가 같은 일도 있었는데 일일 KPI용 컬럼을 추가한다던가 코드를 통해 같은 작업지시의 실시간 KPI는 무조건 갱신시킨다는 등의 방법을 통해 어떻게든 완성할 수 있었다.
