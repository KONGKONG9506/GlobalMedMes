
`src
├── controller       # API 진입점, 요청/응답 DTO 사용, Validation 처리
├── service          # 핵심 비즈니스 로직 집중, 트랜잭션 관리
├── repository       # DB 연동 (JPA), 데이터 접근 로직
├── domain           # 엔티티 클래스 (JPA 기반), DB 테이블과 직접 매핑
├── dto              # 요청(Request), 응답(Response) 객체 (Entity와 분리)
├── config           # 애플리케이션 설정 (보안, DB, Swagger 등)
└── exception        # 공통 예외 처리 전담 (Global Exception Handler)`
### 3.3 DTO / Entity 분리

- **Entity:** 데이터베이스 테이블과 직접 매핑되는 객체로, 데이터의 무결성과 일관성을 유지합니다.
- **DTO (Data Transfer Object):** 클라이언트의 요청(Request) 및 응답(Response)에 따라 필요한 데이터만 담는 객체입니다. Request DTO는 클라이언트로부터 데이터를 받을 때, Response DTO는 클라이언트에 데이터를 보낼 때 사용하며, 각 용도에 맞게 세분화합니다.
    - **요청 DTO 예시:**Java
        
        `public class WorkOrderRequest {
            private Long equipmentId;
            private String orderNo;
            // ... 기타 요청 필드
        }`
        
    - **응답 DTO 예시:**Java
        
        `public class WorkOrderResponse {
            private Long id;
            private String status;
            // ... 기타 응답 필드
        }`
